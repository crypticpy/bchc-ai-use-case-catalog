{%- comment -%} Demo banner: a strip above the header on every page while `_data/site.yml` has `demo: true`, so nobody mistakes the template's sample catalog for a real, published one — the fork's own team on launch day least of all. It is deliberately quiet (a warn-tinted band, one line, no dismiss button): it has to be impossible to miss, but it sits above every page of the site, so it must not read as an error. It goes away on its own — `npm run eject:samples`, `npm run setup` and the "Apply setup" workflow all write `demo: false`. `demo_starter_url` in `_data/site.yml` (optional) is a copy of the template that has already been through the launch guide; when it is set, the banner adds "see what a fresh copy looks like on day one". Tested with `!= ''`, not for truthiness — an empty string is truthy in Liquid. On a showcase example (`site.showcase.role == 'example'`, written into _config by scripts/build_showcase.mjs — see docs/showcase-plan.md) the same strip carries the example switcher instead: which of the template's configurations this site is, and the way to each of the others. Every name and path comes from `site.showcase.examples`, so no preset id is written down here. Without `site.showcase` — a fork, `jekyll serve`, CI — the banner is exactly what it has always been.
