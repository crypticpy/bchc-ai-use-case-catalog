{%- comment -%} "Has anybody looked at this code?" — the rail card on an entry that links to a repository. Two things live here, and only one of them is ever automated: the disclaimer one sentence, on EVERY entry that has a repository link. This catalog links to third-party code; it does not host it, run it, or audit it, and a reader who is about to deploy somebody else's software should hear that from us before they hear anything else. Plain Liquid, server-rendered, no JavaScript involved. the observations what `_data/security_signals.json` recorded about the repository the last time the monthly sweep ran (scripts/security_signals.mjs). Facts about how the project is packaged — last push, archived, license, security policy, public OpenSSF Scorecard — and not one of them inspects what the code does. Rendered only when the file has a record for this entry and that record is `applicable`. The maintainer-set `security_review` field is deliberately NOT here: it is an ordinary `card: fact` select and renders itself in the fact strip and the filter panel like every other field. This card would only duplicate it. Which field holds the repository link is the schema's to say (`entry.repo_key`); no field key is named here. Without the pointer, or without a value on this entry, the whole card renders nothing.
